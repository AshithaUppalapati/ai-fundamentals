## Troubleshooting log

Writing these down so I don't repeat them.

| Problem | Cause | Fix |
|---|---|---|
| `ImportError` inside `openai/__init__.py` | Broken or mismatched `pydantic` import chain | Diagnose with `uv run python -c "import openai"` and read the last line of the traceback. |
| `DLL load failed while importing _pydantic_core: An Application Control policy has blocked this file` | Windows app control (Smart App Control or a managed WDAC/AppLocker policy) blocked a native `.pyd` file | Not a version problem, so upgrading won't fix it. Don't disable security controls. Check whether the machine is managed. |
| `ModuleNotFoundError: No module named 'requests'` | Notebook kernel didn't use `.venv`, and `requests` wasn't added | `uv add requests`, then select the `.venv` kernel and restart it. |
| `KeyError: 'OPENAI_API_KEY'` | Variable not set in the environment | Load it from `.env` with `python-dotenv`. |
| `load_dotenv` returned `False` / `exists: False` | `.env` was inside `.venv\`, not the project root | Moved it to the project root with `Move-Item`. |
| `401 Unauthorized` | Key was loaded but rejected | Check the key's prefix and length, test `/v1/models`, and replace the key if it fails. |

**Lessons so far**
1. Read the **last line** of a traceback first. It has the real error.
2. Check which Python the notebook is using before changing packages.
3. Keep `.env` out of `.venv`. That folder gets regenerated.
4. A `401` means the key is wrong. A `429` means rate limit or quota. A `403` means the key doesn't have permission for that resource.
5. Never paste a key into chat or a notebook cell that might be shared. Revoke it if that happens.

## Chapter 1: Large Language Models

Files: `1_API_Calls.ipynb`, `2_Embeddings.ipynb`

**Key concepts**: API authentication, prompt structure, token limits, embedding vectors, semantic similarity.

### 1. API calls (in progress)
- Model used: `gpt-5-mini`
- Two ways to call the API:
  - **SDK:** `from openai import OpenAI`, then `client.responses.create(...)`, read `response.output_text`.
  - **Raw HTTP:** `requests.post("https://api.openai.com/v1/responses", ...)`. Parse the JSON yourself.
- The SDK is the normal choice. The raw HTTP version helped me isolate the auth and environment problems.

**Questions to answer before moving on**

## Chapter 3: Prompt engineering

Files: `Prompting_Types.ipynb`, `prompt_call.ipynb`

**Key concepts**: prompt templates, context injection, role-based prompting, multi-turn conversations.

| Technique | What it is | When I'd use it |
|---|---|---|
| Zero-shot | Instruction only | Simple, well-defined tasks |
| Few-shot | Instruction plus examples | Output format or style matters |
| Chain-of-thought | Ask for step-by-step reasoning | Multi-step problems |
| Role-playing | Assign a persona or role | Tone or domain framing |
